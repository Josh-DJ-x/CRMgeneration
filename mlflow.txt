MLFLOW EXPERIMENT DATASET
=========================

For the task-oriented results dashboard and research reports, see RESULTS.md.
Start it with: python -m streamlit run dashboard.py
MLflow remains the storage backend; its web interface is optional.

Purpose
-------
Each completed GridWorld CRM task is recorded as one MLflow run in the local
``mlflow.db`` SQLite database by default. A run contains searchable metadata and
metrics, plus JSON/text/GIF artifacts that preserve the full experiment.

One-time setup
--------------
MLflow is an additional dependency. Install it in the active virtual
environment:

    python -m pip install mlflow

Run an experiment normally:

    python system.py

Optional configuration (PowerShell)
-----------------------------------
Choose a different SQLite database:

    $env:MLFLOW_TRACKING_URI = "sqlite:///my_mlflow.db"

Choose an experiment name:

    $env:MLFLOW_EXPERIMENT_NAME = "Honours CRM experiments"

Start the MLflow UI
-------------------
From the project root, after at least one run:

    mlflow server --backend-store-uri sqlite:///mlflow.db --port 5000

Open http://127.0.0.1:5000 in a browser. Select ``CRM GridWorld`` (or your
configured experiment) to compare runs, plot metrics, filter parameters, and
download artifacts.

Viewing results manually
------------------------
The experiment Overview shows MLflow traces, including generator, judge,
training, and evaluation latency. Select the ``Runs`` view to see the ordinary
experiment table: each row is one task execution and contains parameters and
metrics. Open a run, then choose ``Artifacts`` to view or download
``specifications.json``, ``traces.json``, the optional judge reflection, and
the animated GIF.

Traces are created only by runs made after tracing is enabled in this project;
older runs remain valid experiment records but cannot be backfilled with spans.
The Token Usage card remains zero unless a provider exposes token counts to the
application. The Errors card is expected to remain zero for successful runs.

Migrating existing file-store data
----------------------------------
If you already have data in a legacy ``mlruns`` directory, stop any MLflow
server first, then migrate it once before using the SQLite command above:

    mlflow migrate-filestore --source ./mlruns --target sqlite:///mlflow.db

Recorded artifacts
------------------
- specifications.json: difficulty metrics, environment specification, and CRM
  transitions/counters/rewards.
- traces.json: desired and final event traces.
- judge_reflection.txt: the latest judge reflection, created only when the
  judge was called.
- animation/grid_episode.gif: the visual replay of the evaluated episode.

Querying from Python
--------------------
    import mlflow

    mlflow.set_tracking_uri("sqlite:///mlflow.db")
    runs = mlflow.search_runs(experiment_names=["CRM GridWorld"])
    print(runs[["run_id", "params.task_id", "params.success_status",
                "metrics.reward_efficiency", "metrics.episode_reward"]])

    run_id = runs.iloc[0].run_id
    run = mlflow.get_run(run_id)
    print(run.data.params)
    print(run.data.metrics)

    path = mlflow.artifacts.download_artifacts(
        run_id=run_id,
        artifact_path="specifications.json",
    )
    print(path)

The animated GIF can be downloaded through the MLflow UI, or with the same
``mlflow.artifacts.download_artifacts`` function using
``artifact_path="animation/grid_episode.gif"``.
